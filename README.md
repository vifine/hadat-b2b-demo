# Hadat B2B-портал — демо

Рабочая документация проекта (репозиторий приватный, README — для внутреннего пользования). По нему можно восстановить, что сделано, как устроен сайт, как его запускать и где что лежит.

Демо-интерфейс партнёрского B2B-портала Hadat (MVP), собранный по макетам Figma «Hadat B2B портал» (файл `9iyqZI2GvpPw2mHpbYFEFU`, страница «B2B-портал», дизайн-система — страница `0:1`). Это не боевой инструмент: в продакшене данные будут на сервере в РФ, клиенты и заказы — в Битрикс24.

- Адрес: https://hadat-b2b.vifine.tech (GitHub Pages, ветка `main`, файл `CNAME`)
- Демо-вход: `distr@test.example` / `demo-distr` — ООО «Дистрибуция Тест», контакт Алексей Семенов, ценовая группа «Дистрибьютор» (скидка 50% от РРЦ). В базе есть и второй тестовый вход `salon@test.example` / `demo-salon`, но на форме он не показывается.

## Что умеет

- **Вход, заявка на доступ, «заявка принята»** (экраны 01–03). Десктоп: фон-градиент, слева заголовок и вырезанное фото товаров, справа форма. Мобильный: первый экран с фото и кнопкой-якорем к форме. Заявка пишет клиента в Airtable со статусом «Заявка». После заявки — быстрая связь с менеджером (иконки мессенджеров).
- **Главная**: приветствие, плитки «Каталог / Корзина / Заказы» с иконками, баннеры новинок (Style Primer, Detox Therapy, Calm Body Care). Баннер кликабелен целиком и открывает каталог с фильтром. На узких экранах баннеры — автослайдер с точками.
- **Каталог**: товары сгруппированы по базовому названию с вариантами объёма. Оптовая цена с НДС (ниже — без НДС и РРЦ) = РРЦ × (1 − скидка группы), НДС 22%. Наличие: «В наличии / Мало / Нет в наличии». Степпер количества ограничен остатком. Фильтры по категории и линии, «Только в наличии», «Новинки», поиск, сортировка, кнопка «Сбросить фильтры». Новинки помечены зелёным бейджем.
- **Карточка товара** (попап, на мобильном — шторка снизу): все русские поля из Hadat PIM (описание, для кого, компоненты, INCI, применение, аромат, хранение, упаковка, логистика) и степпер количества. Открывается из каталога и из строк заказа; закрывается крестиком, Esc, кликом/тапом по затемнению или по полоске сверху.
- **Корзина**: состав, разбивка НДС, выгода против РРЦ, комментарий, очистка с подтверждением, отправка заказа (статус «Новый» + строки заказа).
- **Заказы**: журнал с цветными статусами, миниатюрами товаров, фильтрами и поиском; страница заказа с итогами и «Повторить заказ».
- **Разделы-макеты** (статичная вёрстка без Airtable, данные-плейсхолдеры в массивах `CLAIMS`, `USERS`, `ADDRS`, `MEDIA`, `FAQ` в `app.js`; изменения не сохраняются):
  - *Рекламации* — рекламация крепится к строке заказа; к одной строке может быть несколько рекламаций с разным количеством и причиной. На странице заказа у каждой позиции кнопка «Рекламация» (форма: количество, причина, комментарий, фото). Раздел «Рекламации» — список со статусами «Новая / На рассмотрении / Решена», фильтр, поиск, пустое состояние.
  - *Пользователи* — сотрудники партнёра, два типа доступа: «Пользователь» (кабинет, приглашение сразу) и «API» (ключ для интеграции). API-ключ запрашивается отдельной формой (название интеграции, система, какие данные нужны, технический контакт, IP, задача) и выдаётся после ручного одобрения менеджером; заявки показываются блоком «Заявки на API-доступ» со статусом «На согласовании» и шагами.
  - *Адреса доставки* — карточки сохранённых адресов, добавить/редактировать (формы-макеты). В корзине адрес выбирается из выпадающего списка, пункт «+ Новый адрес…» раскрывает поля.
  - *Медиа* — библиотека материалов для скачивания с фильтром по разделам.
  - *Справка* — инструкции в формате вопрос-ответ (аккордеон) с поиском и блоком контакта менеджера.
  - *Отгрузки* скрыты из меню (`hidden:true` в `NAV`): понадобятся, когда большой заказ будет отгружаться частями — тогда журнал отгрузок отдельно от журнала заказов.
- **Оболочка**: боковое меню свёрнуто до иконок и раскрывается при наведении (на мобильном выезжает справа), уведомления (колокольчик с красной точкой, пока фиктивные), меню профиля с выходом, плавающая кнопка чата со списком мессенджеров (подпрыгивает каждые 10 с, как на vifine.tech).

Статусы: «На согласовании» (= «Новый» в базе), «Подтверждён» (= Подтверждён / Собирается / Отгружен), «Доставлен», «Отменён». Отгрузка только со склада, поэтому кратности и минимальной партии нет. Все суммы — с копейками.

## Технологии

- Статический сайт без сборки: `index.html` + `app.js` (vanilla JS, SPA на hash-роутинге) + `styles.css`.
- Данные: Airtable REST API напрямую из браузера, тестовая база «Hadat B2B Portal — MVP (тест)» (`appPQgOZVe1hIwsXm`).
- Хостинг: GitHub Pages, домен `hadat-b2b.vifine.tech`.
- Шрифты: Google Fonts — Cormorant Garamond (крупные заголовки), Montserrat (всё остальное).

## Запуск локально

Из корня папки поднять любой статический сервер и открыть в браузере:

```
python3 -m http.server 8000
# http://localhost:8000/
```

Через `file://` открывать не стоит: браузер блокирует загрузку `assets/products-ru.json`.

**Ключ Airtable** задаётся в `config.js` (`window.HADAT_DEMO_KEY`) — персональный токен только на тестовую базу с правами `data.records:read` и `data.records:write`. Если поле пустое, сайт при первом открытии попросит ключ и сохранит его только в этом браузере (localStorage). `config.js` редактируется вручную на GitHub — значение ключа сюда не копировать.

**Кэш версий**: в `index.html` к `styles.css` и `app.js` добавлен `?v=N`. При каждом изменении CSS/JS поднимать номер, иначе браузеры покажут старую версию.

## Структура

- `index.html` — оболочка: шрифты, `styles.css?v=N`, `config.js`, `app.js?v=N`, `<div id="root">`.
- `config.js` — ключ Airtable.
- `app.js`:
  - ID таблиц и полей Airtable (`BASE`, объект `T`), карта статусов `STATUS`, иконки `P` / `ico()`, мессенджеры `MSG`, баннеры `PROMOS`, пункты меню `NAV`;
  - API-слой `api()` / `listAll()` / `create()`;
  - загрузка: `fetchBoot()` / `applyBoot()` / `boot()` — кэш каталога, фоновое обновление `softRefresh()`;
  - роутер `route()`;
  - экраны: `authLayout`, `renderLogin`, `renderApply`, `renderApplied`, `shell`, `renderHome`, `renderCatalog` (`vrowHtml`, `stepper`), `renderCart` (`confirmDialog`, отправка заказа), `loadOrders` / `renderOrders` / `renderOrder`, `openProduct` (попап карточки).
- `styles.css` — все стили; токены цветов в `:root` взяты из дизайн-системы Figma.
- `assets/`:
  - `logo-main.svg` (основной логотип из брендбука), `logo-b2b.svg`, `favicon.svg` (знак HT, прозрачный фон);
  - `hero.jpg`, `hero-mobile.jpg` — фото для экранов входа;
  - `hero-products.webp` — товары, вырезанные с прозрачным фоном из исходника в Figma (узел `88:4493`);
  - `promo-primer.jpg`, `promo-detox.jpg`, `promo-calm.jpg` — баннеры главной;
  - `products/<SKU>.webp` — фото товаров (55 шт., ~5 КБ каждое), скачанные из тестовой базы. Сайт берёт фото отсюда, а не по ссылкам Airtable: ссылки на вложения Airtable временные и через несколько часов перестают открываться. Новый товар без файла здесь покажется по ссылке Airtable; после добавления товаров файлы нужно докачать (список SKU — `LOCAL_IMG` в `app.js`).
  - `products-ru.json` — снимок русских характеристик товаров из Hadat PIM по SKU.

## Данные Airtable

Таблицы тестовой базы: Товары, Ценовые группы, Клиенты, Пользователи портала, Заказы, Строки заказов. ID таблиц и полей — в объекте `T` в начале `app.js`. Все клиенты вымышленные; остатки и скидки — тестовые значения. У ООО «Дистрибуция Тест» в базе ~19 тестовых заказов со всеми статусами.

`products-ru.json` — ручная выгрузка русских полей из Hadat PIM: сайт ходит только в тестовую базу, а не в PIM. При изменениях в PIM файл нужно перевыгрузить и закоммитить.

Для части SKU русские характеристики в карточке пустые (стоит прочерк) — это пробелы в данных PIM, а не баг вёрстки.

## Производительность — сохранять при доработках

- Каталог, ценовые группы и клиенты кэшируются в localStorage (`hadat_b2b_boot_v1`, до 12 ч). При повторном заходе страница показывается сразу из кэша, свежие данные тянутся в фоне и тихо перерисовывают главную, каталог и корзину (если не открыт попап и пользователь не печатает).
- Экран входа не ждёт загрузки каталога: данные догружаются в фоне, отправка формы дожидается их сама.
- Заказы начинают загружаться сразу после входа (`setClient`), поэтому раздел «Заказы» открывается мгновенно. Повторные вызовы `loadOrders()` склеиваются в один запрос.
- `products-ru.json` подгружается заранее, в простое браузера.
- Ассеты лёгкие: фото в webp/jpg до ~100 КБ, картинки каталога — превью Airtable с `loading="lazy"`.

## Проверка перед сдачей

После каждой правки вёрстки прогонять сайт на ширинах 360, 390, 768, 1024, 1280, 1440, 1920 и проверять:
- нет горизонтальной прокрутки, битых картинок и ошибок в консоли;
- главная и экраны входа/заявки на десктопе помещаются в экран без прокрутки;
- попап закрывается по тапу вне его.

Прогон делается в Chromium (Playwright) с эмуляцией iPhone. Safari-специфичные вещи (например, клики по не-кнопкам на iOS) нужно отдельно проверять на живом телефоне.

## История ключевых решений

- Сначала макеты Figma, затем сайт; правки дизайна согласовывались по скриншотам.
- Логотип и подписи на экране входа выровнены по колонке контента на любой ширине; подпись «Портал для партнёров» убрана.
- Форма заявки на десктопе — в три колонки, чтобы вписываться в экран.
- Цвет «Новинки» — зелёный как у WhatsApp (`#25D366`); иконки плиток главной — светлые тона дизайн-системы одинаковой светлоты.
- Карточка товара: на iOS Safari картинка в попапе спозиционирована абсолютно (иначе съезжала).
